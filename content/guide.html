真实机器人强化学习：从任务定义到真机验证路线

这份手册配合《让机器人学会》使用。第 01–03 课通过浏览器倒立摆理解和训练离散动作策略；第 04 课开始用 Python 工程练习连续动作 PPO；第 05–10 课学习建模、辨识和向自己机器人的迁移。浏览器实验使用 MuJoCo 4 的物理仿真和 Double DQN；下面的连续关节 PPO 工程是仿真练习，并非现成已训练的真机项目。

所有方括号都是需要你填的内容。没有测到就写“待测”，不要让 AI 猜测设备型号、寄存器、限位、扭矩或测试结果。本手册没有对你的实体机器人做过装配、带电或运动验证。

1. 先把项目缩小

第一次先选一个关节、一个控制目标。例子可以是“关节从当前位置缓慢跟随一个目标角度，并在误差范围内保持一段时间”。如果现有的普通位置控制器就能很好完成，不必为了使用强化学习而增加复杂度。单关节完成后，才考虑多关节协调、接触、步态和复杂任务。

填一页说明：

项目 填写
机器人、关节、执行器型号 [ ]
期望完成的动作 [ ]
初始姿态和工作范围 [ ]
目标误差、保持时间、测试次数 [ ]
失败条件、停止条件 [ ]
机械支撑、急停、保护方式 [ ]
可用传感器、主控、电源和驱动手册 [ ]
未知及待测项目 [ ]

把“感觉稳定”改成可测标准。比如“误差小于某个阈值并持续某个时间，测试多少次、允许多少次失败”。阈值应依据机械结构、载荷和风险由项目决定，不采用本课程臆造的安全值。

先跟做一个单关节仿真

课程附带 单关节 MuJoCo + PPO 项目说明。示例使用一个虚拟旋转关节和简化位置伺服，每 20 ms 将关节角、角速度、目标角和上一周期实际应用的位置参考按约定归一化后送入策略。网络输出经夹紧、角度映射和参考变化率限制后进入仿真伺服；所有模型参数仅是示例，未对任何真实硬件辨识。

下载项目后进入 project/joint，首次按 README 创建虚拟环境、安装依赖。然后用虚拟环境的 Python：

# 在 joint 目录；先评估随包策略，输出到新目录，保留随包原始记录
.\.venv\Scripts\python.exe evaluate.py --output first_check

# 独立训练新策略并输出到 my_run
.\.venv\Scripts\python.exe train.py --timesteps 100000 --seed 123 --output my_run
.\.venv\Scripts\python.exe evaluate.py --model my_run\joint_ppo.zip --output my_run
.\.venv\Scripts\python.exe export_onnx.py --model my_run\joint_ppo.zip --output my_run
.\.venv\Scripts\python.exe check_deployment.py --artifacts my_run
.\.venv\Scripts\python.exe deploy_offline.py --model my_run\joint_actor.onnx

最后一条只对示例数字做推理并打印结果，不会连接设备或发送电机指令。模型 ONNX 中包含 [-1,1] 动作夹紧，但位置参考的缩放和每周期限速由模型图外的 contract.py 实施；第四个观察使用的是上次限速后实际参考，不是上次网络的原始输出。

制作时在同一简化模型、20 组训练外初始条件的一次评估中，末尾 50 步平均绝对误差：未训练网络 0.4915 rad、PPO 0.0091 rad、直接把目标角作为位置参考的简单基线 0.0286 rad；后两者均为 20/20 满足成功判据：整回合没有提前失败，且最后 20 步每一步误差均小于 0.05 rad。原始记录在 project/joint/artifacts/evaluation.json。这只是一组仿真结果，不表示 PPO 一定优于其他控制器，也不代表真实关节已经验证。

2. 通用接口合同：训练与部署必须一致

训练好的策略不会理解“这是左腿还是右腿”，它只按固定顺序读数字。给每一个元素填表，训练、评估、部署使用同一版本。

2.1 输入：策略看见什么

序号 名称 来源 单位 零点/坐标系/正方向 归一化 时间/更新频率 可在真机取得？
0 [关节角 q] [编码器] rad [零位和正方向] [均值、缩放、裁剪] [ ] [ ]
1 [关节角速度 dq] [传感器或估计] rad/s [和 q 一致] [ ] [ ] [ ]
2 [目标角 q_goal] [任务命令] rad [同一坐标系] [ ] [ ] [ ]
3 [上一动作] [软件状态] [按定义] [ ] [ ] [ ] [ ]

这只是单关节示例。实际观察需要按任务重新设计，模型训练前固定顺序；若策略依赖历史帧或状态估计，还必须描述窗口长度、滤波延迟和初始化方式。IMU 的姿态约定、重力方向、四元数顺序等也要写入，不可只写“IMU 数据”。

例如某设备手册确认反馈为输出轴每圈 4096 计数，零点为 1024，正方向为正，当前读数 2048，则角度 q = (2048−1024) × 2π/4096 = π/2 rad。这是算术示例；不同设备可能报告电机轴而非输出轴，也可能使用多圈或不同零点。先查型号和固件手册，减速比不要重复应用。

2.2 输出：策略希望机器做什么

序号 关节名/设备 ID 控制模式 策略值范围 实际命令与单位 物理上限/限速 更新周期 失联或故障动作
0 [ ] [位置/速度/力矩] [ ] [ ] [ ] [ ] [ ]

一个可供理解的例子：如果策略输出归一化数值 a ∈ [-1,1]，定义 q_mid=(q_min+q_max)/2、q_half=(q_max−q_min)/2，则 q_command=q_mid+a×q_half。训练和部署必须使用同一映射。实际位置边界、限速和加速度应结合设备及结构建立独立保护；不要把例子的数字当作安全参数。

软件还应检查有限数值、时间戳是否过期、动作是否越界、上次命令和状态是否有效。失联后的安全动作依赖具体设备：悬空重力负载直接失去力矩可能坠落，需要考虑支撑、制动、断电和驱动器实际能力。重连或重启后，不能自动恢复旧目标。

2.3 时间合同

  • 记录物理步长、每次动作保持几个物理步、策略周期、驱动更新周期和传感器更新周期。
  • 例如物理步长 0.002 秒，保持 10 步，策略周期就是 0.020 秒，即 50 Hz。这只是换算例子，不是默认推荐频率。
  • 记录测量、推理、总线传输各自的时间戳或耗时，以及丢包和超时；不同设备时钟需先对齐。
  • 观测做滤波会引入延迟；真机使用了什么处理，仿真应能复现足够接近的处理。

3. 位置型总线舵机和无刷驱动怎么对齐

要检查什么 总线舵机常见情况 无刷电机和驱动器常见情况
软件接口 串行等总线，设备 ID，寄存器/协议依型号不同 驱动器提供 CAN、串口或其他接口，依设备不同
命令类型 可能支持位置、速度、电流等模式，不同型号不同 可支持位置、速度、力矩等模式，不同驱动器不同
内部控制 可能集成位置/速度闭环及运动曲线、限速 常见级联位置、速度和电流闭环
反馈 位置、速度、电流、温度和错误项是否支持需查手册 编码器位置/速度、电流、母线电压及故障依驱动器而定
建模重点 零点、方向、速度限制、总线更新率、回差和内部滤波 模式、编码器、电流/力矩限制、减速比、带宽和保护

每种都是常见情况，不代表某个具体型号一定支持。电流与力矩之间的关系还受电机常数、传动效率和工作状态影响；没有标定时，不要把设备“负载”或命令电流当作实测输出轴力矩。不同设备寄存器地址也不能照搬。

4. 单关节系统辨识工作单

先在网站第 07 课点击“打开网页辨识实验”，再点“开始拟合与验证”：用合成目标和响应理解怎样分开拟合与留出验证。也可下载离线 Python 练习。练习的参数和曲线是合成的，不代表真实电机；拟合有效延迟不能直接当作纯通信延迟。

只有在现场机械支撑、有效限位、急停、设备手册和电源保护都确认后，才设计小范围、低速度的单关节输入；具体安全值必须由硬件条件决定。先记录操作条件，任何故障或异常立即停止并排查。

推荐 CSV 字段：

session_id,sample_time_monotonic_ms,command_time_ms,feedback_time_ms,joint_name,device_id,mode,command_value,command_unit,position_raw,position_rad,velocity_rad_s,measured_current_A,bus_voltage_V,temperature_C,feedback_age_ms,device_error,limit_flag,note

字段未被设备提供就留空并标记“不支持”或“未测”，不要把空值填成零。保存设备型号、固件版本、采样率、机械安装、负载、指令限制、采集软件和时间同步方式。

现象 怎样观察 对仿真的意义
时延 对齐命令时间和反馈响应时间，估计且保留不确定度 指令/传感延迟与动作保持时间
跟随快慢 比较输入和输出曲线的上升过程 内部闭环、惯性和限速
超调与振荡 观察是否越过目标及衰减过程 阻尼、增益与模型缺项
饱和 不同命令或负载下响应是否被限制 速度、电流或力矩约束
反向间隙 比较低风险正反方向的响应差异 齿隙、摩擦、死区

用一部分记录拟合模型，再在预留的不同输入或负载数据上比较时延、误差及曲线形状。记录拟合值、留出误差与限制；一条曲线拟合良好不代表所有工况都好。

5. 连续动作 PPO：你需要理解的训练流程

  1. 环境以固定周期返回观察，策略网络按当前观察给出动作分布。
  2. 训练时从分布采样动作，环境执行后返回奖励与下一观察；连续收集一批轨迹。
  3. 价值网络估计状态的未来回报；与实际/估计回报比较，得到“比通常预期更好还是更差”的优势估计。
  4. PPO 根据新旧策略对这些动作的概率或概率密度之比更新策略，用裁剪目标减少过大变化的激励；价值网络同时拟合回报。裁剪不是硬安全限制，也不保证每次都变好。
  5. 用新的策略继续采样。单独评估时记录成功率、误差、失败类型和对未见过条件的表现，而不是只看训练奖励。

训练时和部署时的探索处理应写清楚。导出的策略不必包含训练器，但必须带上版本、观察归一化、动作缩放、输入输出形状与单位等配套资料。不同模型或导出方式包含的前后处理不同，必须用固定输入逐项对照；SB3 的 ONNX 示例明确提示连续动作的后处理需要额外考虑。

6. 从仿真到硬件：逐级证据

阶段 要做的事 通过证据 不代表什么
A 模型自检 重力、关节轴、方向、范围、碰撞、基本响应 模型版本和自检记录 还未验证真实硬件
B 仿真训练 固定配置训练，独立条件评估并记录失败 配置、种子、策略、归一化、评估日志 高分不保证真机安全
C 模型辨识 对已确认安全的条件记录真实响应，拟合并留出数据复核 原始时序、条件、模型与误差 一种工况拟合不覆盖全部场景
D 离线对照 相同固定输入分别进入训练端与新主控推理，逐元素比较 输入、两侧输出、误差、容差、版本 没有验证机械运动
E 影子运行 真实传感输入只供推理和记录，不发送电机运动指令 输入时序、预测输出、对齐检查、故障注入 没有验证带电运动
F 保护和通信 根据设备检查通信、超时、急停和安全状态 设备状态与故障记录 不等于全速或全负载可用
G 单关节受保护测试 受支撑，按设备和项目条件从最小动作开始 操作者、条件、输入、反馈、故障与通过标准 不等于多关节任务已验证
H 扩展测试 逐级扩大关节、范围、速度、载荷和任务 每一级的独立记录 不能省略现场判断

每一级在执行前写下进入条件、停止条件和通过标准。出现不符合预期的行为，停止并回到上一级查证。真实测试必须由现场人员按设备和结构完成；AI 可协助整理代码与数据，不能代替现场支撑和急停。
